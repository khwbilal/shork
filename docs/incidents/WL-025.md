# WL-025: Test servers kept running after they were "stopped"

- **Work-log item:** [WL-025](../work-log.md)
- **Date:** 2026-10-21
- **Severity:** medium (a stale backend with the real `.env` served requests for about 25 minutes; no AI call reached it, so no plan usage was spent)

## Context

Assessing the major bumps of WL-025: a Vite 8 dev server in a scratch copy, proxying `/api` to a backend on port 8000 started with `AI_PROVIDER=none`.

## Symptom

The test backend exited at once:

> ERROR: [Errno 10048] error while attempting to bind on address ('127.0.0.1', 8000): [winerror 10048] only one usage of each socket address (protocol/network address/port) is normally permitted

Yet the page in the browser reached a backend on port 8000 whose rail chip read "Claude subscription", so some other server with the real configuration was answering.

## Diagnosis

`Get-NetTCPConnection -LocalPort 8000` named PID 15468, which no longer existed. Its child PID 26628 did: `python.exe -c "from multiprocessing.spawn import spawn_main; spawn_main(parent_pid=15468, ...)" --multiprocessing-fork`, created 20:10:44, the moment of the `start.ps1 -Keep` test in WL-010. `uvicorn --reload` serves from a multiprocessing child that inherits the listening socket. The cleanup after that test stopped processes whose command line contained `uvicorn`; the child's command line does not, so it survived and kept serving with the code and `.env` of that moment.

A sweep of all test ports then found the same pattern for **every** Vite dev server started that day (5173, 5174, 5175): stopping a background task ends its `bash.exe` wrapper, but the `npx`, `cmd` and `node vite.js` processes beneath it keep running.

## Fix

Stopped PID 26628 and the 15 `bash`, `npx`, `cmd` and `node` processes of the three Vite servers. Verified: no listener on 8000, 8765 to 8770 or 5173 to 5175; no `uvicorn`, `vite` or `spawn_main` process left. Removed the empty `backend/data` the stale server had created.

## Prevention / follow-ups

- After stopping any test server on Windows, verify the port is free (`Get-NetTCPConnection -LocalPort <port> -State Listen`) and kill the whole process tree, matching `spawn_main` children and `node ... vite.js`, not just the command that started it. Added to the gotchas in [project-state.md](../project-state.md).
- Prefer starting test backends without `--reload` (one process, nothing inherits the socket).
- Proposed ruleset 10.7 addition, pending Sheryar's approval (ruleset 0.1): "Stopping a background task leaves child processes running on Windows; after every test server, check the port is free and stop the process tree."
