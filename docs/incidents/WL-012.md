# WL-012: The AI never saw the confluence score

- **Work-log item:** [WL-012](../work-log.md)
- **Date:** 2026-10-21
- **Severity:** high (every analysis from every provider was affected since before this repo's recorded history)

## Context

First real analysis through the new Claude subscription provider (WL-010), SOLUSDT 1h.

## Symptom

The reply said:

> SETUP: n/a (setup field truncated)
> SCORE: n/a/10, confluence missing from snapshot, so no directional trade can be confirmed

The model answered Neutral; the confluence guard then upgraded the plan to Buy, so the card and the plan disagreed.

## Diagnosis

`market.py:context_to_prompt_block` serialised the condensed snapshot with `json.dumps(indent=2)` and cut it at 5,000 characters. A typical snapshot was about 6,500 characters, and `setup` and `confluence` were the **last** keys in `condense_market_context`, so the cut always removed them. The system prompt tells the model to obey `snapshot.confluence`, which it never received. It went unnoticed because the backend guard applied the score anyway, and with no AI key (the state of earlier sessions) the stub never reads the snapshot.

## Fix

Compact JSON (no indentation), empty values pruned, `pair`, `timeframe`, `price`, `setup` and `confluence` placed first, the duplicate `setup` inside `confluence` dropped, and a budget of 8,000 characters enforced by dropping low-value sections whole (`pivots`, `level_hints`, SMAs and so on) before any cut. Typical size is now about 4,500 characters with nothing truncated. The next real analysis quoted "SCORE: 8.6/10".

## Prevention / follow-ups

- [Decision 0003](../decisions/0003-guards-decide-the-bias.md) states that the snapshot must always contain `setup` and `confluence`; `CLAUDE.md` says the same.
- WL-013 added the `DESK OVERRIDE` line, so a model and guard disagreement is visible instead of silent.
- WL-018 should pin this with a test: `context_to_prompt_block` keeps `setup` and `confluence` and stays within budget.
